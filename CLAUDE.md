# CLAUDE.md — rules for working on "Tcl to Tapeout"

Source of truth: `PRD.md`. This file summarises its non-negotiable rules (§0, §4, §12, §14, §15).
Work **phase by phase** (PRD §17): finish a phase, run its acceptance checks, then **stop for human review**.

## §0 Process rules
1. One phase at a time; stop and ask for review before the next.
2. Ambiguous requirement → pick the simpler option and log it in `docs/decisions.md`.
3. **Never invent Calibre syntax.** Every Calibre DESIGNrev command shown to learners carries a status badge (✅ verified / ⚠️ verify, table in PRD §10.2 and `docs/calibre-command-status.md`). ⚠️ commands are presented as "DRV-Lite form; verify against the official Calibre DESIGNrev Reference Manual".
4. Every runnable Tcl block (```` ```tcl run ````) is tested in CI on Tcl 8.6 **and** 9.0. Version-dependent behaviour goes in a `<VersionNote>`.
5. Quality benchmark: Week 3 ("golden week", Phase 2). All later content matches its structure, tone, depth.
6. Do not copy text from Siemens manuals, Tcl man pages or tutorials. Paraphrase and link under "Further reading".
7. AI-assisted content is never published unreviewed: every lesson/lab/quiz bank has `ai_assisted`, `reviewed_by`, `review_date` frontmatter. Empty `reviewed_by` ⇒ visible "Draft — not yet reviewed" banner (implemented in `src/routeMiddleware.ts`).
8. From M30 on, **no Tcl-9-only features** in learner code (Calibre's embedded Tcl version is unknown).
9. Decisions already taken, do not reopen: code runs on 8.6 and 9.0; Weeks 1–10 in-browser; local tclsh from Week 11; no Calibre licence/manual (M30–M40 use DRV-Lite + KLayout only).

## §4 Tech stack
Astro + Starlight, MDX in `src/content/docs/`, small TS islands (Preact/vanilla), Wacl (Tcl 8.6.6 in WASM, self-hosted in `public/wacl/`, behind a swappable `TclRuntime` interface), KaTeX, hand-authored SVG diagrams, Expressive Code, GitHub Pages via Actions, `tcltest` on 8.6+9.0, `starlight-links-validator`, npm with committed lockfile. M10 code must use only Tcl 8.6.6 features. Keep JS small: lesson page < 150 KB JS without the playground.

## §12 Content writing
- Grade 9–10 reading level, short active sentences, "you".
- Define every term on first use with `<GlossaryTerm>`; no unexplained acronyms.
- One idea per paragraph; ≤ 150 words between interactive elements; ≤ 3 goals per lesson.
- Consistent analogy: the chip is a city map drawn in layers.
- Code style: 4-space indent; always brace `expr` and `if`/`while` conditions; descriptive names; no clever one-liners in M10.
- Expected outputs come from real runs, never hand-written.
- Calibre commands only from §10.2, inside `<RealCalibre>` with correct status.
- Every lesson lists `sources:` and "Further reading"; paraphrase, quotes ≤ 1 short sentence.
- Encouraging tone; errors are normal and useful. Diagrams have descriptive alt text.

## §14 Legal & trust
- Code MIT, content CC BY-SA 4.0.
- The Siemens non-affiliation disclaimer appears in the footer, About page and DRV-Lite README. DRV-Lite is never called `calibredrv`.
- No copied Siemens text/figures/examples; link to public KB articles.
- Record third-party licences in `docs/third-party.md`. KLayout (GPL) is not bundled.
- No tracking or analytics; progress stays in the browser (localStorage in try/catch).
- AI-assistance disclosure on About page and footer.

## §15 Build, CI, deploy
- `ci.yml`: `npm ci && npm run build`, schema validation, link validation, snippet tests (8.6 + 9.0), DRV-Lite tests (8.6 + 9.0), lab tests vs private solutions when available.
- `deploy.yml`: build + deploy to GitHub Pages on push to `main`.
- Snippets: `scripts/extract-snippets` → `snippets/`, `scripts/run-snippets.tcl` compares stdout exactly; a 8.6/9.0 mismatch fails unless inside a `<VersionNote>` with per-version outputs.
- Budgets: LCP < 2.5 s, Lighthouse a11y ≥ 95, Wacl loaded lazily.
