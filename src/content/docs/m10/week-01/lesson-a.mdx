## Scripts, commands and output

A <GlossaryTerm term="script" /> is a list of instructions for the computer, written as plain text, like a recipe. Each instruction is a <GlossaryTerm term="command" />, and each command sits on its own line. The computer runs the commands one after another, from top to bottom.

This course writes scripts in <GlossaryTerm term="tcl" />, said "tickle". Many chip-design tools understand Tcl, which is why you learn it here.

Your first command is `puts`, short for "put string". A string is a piece of text. `puts` prints one line of text, then moves to the next line.

<Diagram name="w01-script-run" alt="On the left, a script of three numbered lines: a comment, # Lumen-1 passport, then puts with Lumen-1 in quotes, then puts with Size: 400 x 300 um in quotes. An arrow says Tcl runs the commands from top to bottom. On the right, the output has two lines, Lumen-1 and Size: 400 x 300 um. A note says the comment prints nothing and each puts command prints one line." />

## Comments: notes for humans

A <GlossaryTerm term="comment" /> is a note for the people who read your script, including you next month. A line that starts with `#` is a comment. Tcl skips the whole line, so a comment never changes the output.

Good comments say what a part of the script is for. Put them on their own line, just above the code they explain.

<WorkedExample
  code={`# Lumen-1 passport, version 1
# It prints the chip's name and size.
puts "Chip: Lumen-1"
# The size is width x height, in micrometres
puts "Size: 400 x 300 um"`}
  notes={{
    1: 'The # at the start makes this whole line a comment. Tcl skips it. It names the script, like a title.',
    2: 'Another comment, saying what the script does.',
    3: 'A command. Output: Chip: Lumen-1',
    4: 'A comment can sit between commands, to explain the line below it.',
    5: 'Output: Size: 400 x 300 um. Five lines of script, but only two lines of output: the three comments print nothing.'
  }}
/>

## Predict → Run → Explain

Before you run, type what you think the output will be. Run unlocks once you have typed something. Your guess does not need to be right: a wrong guess shows you exactly what to learn next.

  expected={`SENSOR

  explanation="Lines 1 and 3 start with #, so they are comments, and Tcl skips them, even though line 3 looks like code. In line 4 the line starts with puts, so it is a command. The # is inside the text that puts prints, so it appears in the output."

## Common traps

When Tcl cannot run a command, it stops and shows an <GlossaryTerm term="error-message">error message</GlossaryTerm>. Errors are normal: every programmer sees them every day. Read the message first. It usually names the exact word that Tcl did not understand.

<Trap
  wrong={`Puts "Hello, Lumen-1"`}
  error={`invalid command name "Puts"`}
  fix={`puts "Hello, Lumen-1"`}
  why="Tcl is case-sensitive: capital and small letters are different. Puts and puts are two different names, and only puts exists. The message invalid command name means Tcl does not know the first word of the command, and it shows you that word."
/>

<Trap
  wrong={`Passport for Lumen-1
puts "Name: Lumen-1"`}
  error={`invalid command name "Passport"`}
  fix={`# Passport for Lumen-1
puts "Name: Lumen-1"`}
  why="A note without # is not a comment. Tcl thinks it is a command and tries to run its first word, Passport, which does not exist. Start every note with #."
/>

<Trap
  wrong={`puts “Hello Lumen-1”`}
  error={`can not find channel named "“Hello"`}
  fix={`puts "Hello Lumen-1"`}
  why="Word processors and chat apps often turn straight quotes into curly ones, like “ and ”. Tcl only understands the straight quote mark. With curly quotes, the space splits the text into two pieces, and puts thinks the first piece, “Hello, names a place to print to, called a channel. Type code in the playground or in a plain text editor, not in a word processor."
/>
