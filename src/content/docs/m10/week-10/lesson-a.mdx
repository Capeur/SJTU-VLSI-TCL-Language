## error: stop with a clear message

You have seen many <GlossaryTerm term="error-message">error messages</GlossaryTerm> from Tcl itself. Your own procs can raise errors too. `error "message"` stops the proc at once, and the script with it, and shows your message.

Use it when a proc gets a value it cannot work with. A width of −5 µm makes no sense, so returning a "result" would hide the problem. A good message says what is wrong and shows the value: `width must be positive, got -5`.

<WorkedExample
  code={`proc blockArea {w h} {
    if {$w <= 0} {
        error "width must be positive, got $w"
    }
    return [expr {$w * $h}]
}
puts [blockArea 120 80]`}
  notes={{
    1: 'A proc with two arguments, the width and the height of a block.',
    2: 'Check the input first: is the width impossible?',
    3: 'If it is, stop here with a clear message. Nothing after this line runs.',
    4: 'The end of the check.',
    5: 'Only good input reaches this line.',
    6: 'The end of the proc.',
    7: 'A good block. Output: 9600'
  }}
/>

Now run the same proc with a bad width. The script stops, and your message is the error message.

<TclPlayground client:visible fails={`width must be positive, got -5`} code={`proc blockArea {w h} {
    if {$w <= 0} {

}

## catch: a safety net

`catch {script} message` runs the script and catches any error in it, so your own script goes on. It gives back a code: **0** if all went well, **1** if there was an error. The variable you name, here `message`, receives the result, or the error message.

That fits an `if`: `if {[catch {…} message]} {…}` runs its body only when something went wrong. Brace the script, just like a loop body: `catch` must receive the code, not its result.

<Diagram name="w10-error-stops" alt="Two rows of three blocks. Top row, without catch: the block 120 by 80 gives 9600, the block minus 5 by 10 gives an error, and the block 100 by 80 never runs, because the script stops at the bad block. Bottom row, with catch: area 9600, then skipped minus 5 by 10, then area 8000: the bad block is reported and the script goes on. A note says catch gives 1 and the message on an error, 0 and the result when all goes well." />

<WorkedExample
  code={`proc blockArea {w h} {
    if {$w <= 0} {
        error "width must be positive, got $w"
    }
    return [expr {$w * $h}]
}
foreach size {{120 80} {-5 10} {100 80}} {
    set w [lindex $size 0]
    set h [lindex $size 1]
    if {[catch {blockArea $w $h} result]} {
        puts "skipped $w by $h: $result"
    } else {
        puts "area $result um2"
    }
}`}
  notes={{
    1: 'The same proc as above.',
    7: 'Three blocks, one of them bad.',
    8: 'The width of this block.',
    9: 'The height.',
    10: 'Run the call inside catch. 1 means an error: result then holds the error message.',
    11: 'Output for the bad block: skipped -5 by 10: width must be positive, got -5',
    12: '0 means all went well: result holds the area.',
    13: 'Output: area 9600 um2 for the first block, area 8000 um2 for the last one.',
    15: 'The loop reaches every block. The bad one did not stop it.'
  }}
/>

## errorInfo: where did it break?

The message says WHAT went wrong. To see WHERE, read the <GlossaryTerm term="stack-trace">stack trace</GlossaryTerm>. After an error, Tcl keeps it in the variable `errorInfo`: first the message, then "while executing" and the command that failed, then one "invoked from within" line for each level further out.

Here the error starts in `blockArea`, which was called by `reportBlock`. Run it and read the trace from the top. Inside a proc, you would write `global errorInfo` first (Week 7).

<TclPlayground client:visible code={`proc blockArea {w h} {
    if {$w <= 0} {
        error "width must be positive, got $w"
    }
    return [expr {$w * $h}]
}
proc reportBlock {name w h} {
    return "$name: [blockArea $w $h] um2"
}
if {[catch {reportBlock SPARE -5 10} message]} {
    puts "Message: $message"
    puts "Trace:"
    puts $errorInfo
}`} />

## Common traps

<Trap
  wrong={`catch [expr {1 / 0}] message
puts "still running"`}
  error={`divide by zero`}
  fix={`catch {expr {1 / 0}} message
puts "still running"`}
  why="With brackets, Tcl runs expr BEFORE catch even starts (Week 2), so the error happens outside the safety net and stops the script. Braces hand the code itself to catch, which runs it inside the net."
/>

<Trap
  wrong={`if {[catch {expr {6 / 2}} result]} {
    puts "fine: $result"
} else {
    puts "error: $result"
}`}
  output={`error: 3`}
  fix={`if {[catch {expr {6 / 2}} result]} {
    puts "error: $result"
} else {
    puts "fine: $result"
}`}
  why="catch gives 1 when there WAS an error, and 0 when all went well. So the body of the if is the error branch. Read it as: if catching found an error…"
/>

<Trap
  wrong={`error width must be positive`}
  error={`wrong # args: should be "error message ?errorInfo? ?errorCode?"`}
  fix={`catch {error "width must be positive"} message
puts $message`}
  why="error takes ONE word for its message. Without quotes, the message is four words, so error gets too many arguments. Put the message in quotes, like the text of puts."
/>
