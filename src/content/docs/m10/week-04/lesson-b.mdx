## while: repeat while a test is true

First, a small helper. `incr x` adds 1 to the variable x, and `incr x 50` adds 50. It works on whole numbers only. Like `set`, it takes the variable's name, with no `$`, because it changes what is in the box.

Now the loop. `while {condition} {body}` checks the condition. If it is true, while runs the <GlossaryTerm term="loop-body">body</GlossaryTerm>, then checks the condition again. Each run of the body is called a pass. When the condition is false, the loop ends and the script goes on.

Something in the body must change what the condition tests, or the loop never ends. Here, `incr x` moves x one pitch further on every pass.

<Diagram name="w04-while-loop" alt="The cycle of a while loop, for while dollar x less than dollar chipWidth. Step 1: check the condition. If it gives 1, true, step 2 runs the body: print a stripe, then incr x, and goes back to the check. If it gives 0, false, step 3: go on after the loop. Below, the values of x at each check: 50, 100, 150, 200, 250, 300 and 350 are true, so a stripe is printed each time; at 400 the check is false and the loop ends." />

<WorkedExample
  code={`set chipWidth 400
set pitch 50
set x 50
while {$x < $chipWidth} {
    puts "Stripe at x = $x um"
    incr x $pitch
}
puts "Done"`}
  notes={{
    1: 'Lumen-1 is 400 µm wide.',
    2: 'One stripe every 50 µm.',
    3: 'The first stripe sits 50 µm from the left edge.',
    4: 'Check: is x still inside the chip? 50 < 400 is true, so the body runs.',

    6: 'Move to the next stripe: x becomes 100. Then while checks the condition again.',
    7: 'The end of the body. Passes 2 to 7 print 100, 150 and so on up to 350. Then x is 400, 400 < 400 is false, and the loop ends.',

## for: count from a start to an end

Many loops follow the same pattern: set a variable, test it, run the body, change the variable. `for` writes the first three parts in one line, so you cannot forget one:

`for {start} {condition} {next} {body}`

for runs start once. Then, on every pass, it checks the condition, runs the body, and runs next. When a variable only counts the passes, it is called a <GlossaryTerm term="counter" />.

<WorkedExample
  code={`set x 290
for {set pad 1} {$pad <= 4} {incr pad} {
    puts "Pad $pad at x = $x um"
    incr x 25
}`}
  notes={{
    1: 'The PADS block starts at x = 280 µm. The first pad sits 10 µm inside it.',
    2: 'start: pad is 1. condition: is pad at most 4? next: incr pad after every pass. So the body runs for pad = 1, 2, 3 and 4.',
    3: 'Output on the first pass: Pad 1 at x = 290 um',
    4: 'The pads have a 25 µm pitch, so x moves on too. The counter and x both change on every pass.',
    5: 'After pass 4, pad becomes 5, 5 <= 4 is false, and the loop ends. The last line printed is: Pad 4 at x = 365 um'
  }}
/>

## Why loops need braces

Week 3's one-pass rule explains the braces. Tcl substitutes a command's words once, before the command runs. But while must check its condition again on every pass, so the condition has to reach while unchanged, as `$x < 400`. Braces do exactly that. In double quotes, Tcl would replace `$x` once, before the loop starts, so while would receive `0 < 400` and test it forever. The body needs braces for the same reason: it must run fresh on every pass.

A loop that never ends is an <GlossaryTerm term="infinite-loop">infinite loop</GlossaryTerm>. Its usual cause is a forgotten `incr`: if nothing in the body changes x, the condition stays true. The playground stops any run after 5 seconds and asks whether you have an infinite loop.

<Diagram name="w04-braced-loop" alt="Two columns, starting from set x 0. With quotes, wrong: Tcl substitutes once, before while starts, so while receives 0 less than 400 and checks that on every pass; x grows, but the test never sees it, so it is always true and never stops. With braces, right: while receives dollar x less than 400 and looks up x again on every pass, 0, 50, and so on up to 400 less than 400, which is false at last, so the loop ends." />

## Common traps

<Trap
  wrong={`set i 0
while {$i < 3} "
    puts $i
    incr i
"`}
  output={`0
0
0`}
  fix={`set i 0
while {$i < 3} {
    puts $i
    incr i
}`}
  why="The body is in double quotes, so Tcl replaced $i with 0 once, before while started. Every pass runs puts 0. incr i still works, because it names the variable without a $, so the loop does stop. Braces keep the body unchanged, so $i is read fresh on every pass."
/>

<Trap
  wrong={`set x 0
incr x 0.5`}
  error={`expected integer but got "0.5"`}
  fix={`set x 0
set x [expr {$x + 0.5}]
puts $x`}
  why="incr only adds whole numbers. To add a decimal, work out the new value with expr and store it with set."
/>

<Trap
  wrong={`for {set pad 1} {$pad < 4} {incr pad} {
    puts "Pad $pad"
}`}
  output={`Pad 1
Pad 2
Pad 3`}
  fix={`for {set pad 1} {$pad <= 4} {incr pad} {
    puts "Pad $pad"
}`}
  why="The PADS block has four pads, but this loop stops when pad reaches 4, so pad 4 is missing. Counting from 1 to 4 needs <= 4. When a loop runs one pass too few or too many, check the condition first."
/>
