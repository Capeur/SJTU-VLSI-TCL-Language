## An array: a family of variables

An <GlossaryTerm term="array" /> is a group of variables that share one name. Each one, an element, is picked by a key in parentheses: `count(METAL1)`, `count(POLY)`. You use an element like any variable: `set count(POLY) 0`, `$count(POLY)`, `incr count(POLY)`. The key can come from a variable: `$count($layer)`.

`incr` on an element that does not exist yet starts it at 0, so counting needs no setup. `array size count` gives the number of elements, and `array names count` the list of their keys.

<WorkedExample
  code={`set shapeLayers {VIA1 POLY METAL2 VIA1 POLY VIA1}
foreach layer $shapeLayers {
    incr count($layer)
}
puts "VIA1: $count(VIA1)"
puts [array size count]
foreach layer [lsort [array names count]] {
    puts "$layer: $count($layer)"
}`}
  notes={{

## array names: no promised order

A dict keeps its keys in insertion order. An array does not. `array names` gives every key, but **in an order that Tcl does not promise**. It is not the order you added them, and not sorted either. It may differ between Tcl versions, and it may change as the array grows.

So never let your output depend on it. When the order matters, sort the names with `lsort [array names count]`, or walk a dict that holds the order you want, as the lab does.

<Diagram name="w09-dict-vs-array" alt="Top: a dict drawn as a row of numbered boxes in order, 1 ACTIVE 1.0, 2 POLY 2.0, 3 METAL1 4.0, then more: dict keys and dict for follow the order the keys were added. Bottom: an array drawn as separate boxes scattered in a bag, gds(METAL1), gds(ACTIVE), gds(POLY): array names gives every name, but in an order that is not promised. lsort of array names gives a fixed, sorted order." />

## dict or array?

Both map keys to values. The difference is what they are.

| | dict | array |
|---|---|---|
| What it is | one **value**, like a list | a family of **variables** |
| Order | insertion order | no promised order: sort it |
| Pass to a proc, return it | yes, like any value | no: pass its name and use `upvar` |
| A record inside it | yes: nested dicts | no: one level only |
| Change one element | `dict set d key value` | `set a(key) value`, `incr a(key)` |

A good rule: use a **dict** for a table you pass around, nest, or print in order; use an **array** for a few counters that you change in place.

<WorkedExample
  code={`proc addLayer {table name number} {
    dict set table $name $number
    return $table
}
set gdsNumbers [dict create POLY 2.0]
set gdsNumbers [addLayer $gdsNumbers VIA1 5.0]
puts $gdsNumbers
proc addCount {arrayName layer} {
    upvar 1 $arrayName counts
    incr counts($layer)
}
addCount shapes METAL1
addCount shapes METAL1
puts "METAL1: $shapes(METAL1)"`}
  notes={{
    1: 'A dict goes in as a VALUE, like a list.',
    2: 'This changes the proc’s own copy, table.',
    3: 'Send the new dict back.',
    4: 'The end of the dict version.',
    5: 'A table with one layer.',
    6: 'Store what the proc returns. Output of the next line: POLY 2.0 VIA1 5.0',
    7: 'Print the new table.',
    8: 'An array cannot travel as a value. The proc gets its NAME instead.',
    9: 'Week 7’s upvar: counts now means the caller’s array.',
    10: 'This changes the caller’s array directly. Nothing to return.',
    11: 'The end of the array version.',
    12: 'Pass the name shapes, without $.',
    13: 'The second call adds 1 again.',

## Common traps

<Trap
  wrong={`foreach layer {POLY VIA1 POLY} {
    incr count($layer)
}
puts $count`}
  error={`can't read "count": variable is array`}
  fix={`foreach layer {POLY VIA1 POLY} {
    incr count($layer)
}
puts "POLY: $count(POLY)"`}
  why="An array is a family of variables, not one value, so $count alone means nothing to Tcl. Read one element with $count(POLY). To see them all, loop over lsort [array names count]."
/>

<Trap
  wrong={`set count(METAL1) 12
puts $count(metal1)`}
  error={`can't read "count(metal1)": no such element in array`}
  fix={`set count(METAL1) 12
puts $count(METAL1)`}
  why="Keys are exact, and capitals count: metal1 and METAL1 are two different elements. Clean a typed name first with string toupper (Week 8)."
/>
