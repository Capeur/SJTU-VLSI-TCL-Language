## Keys and values

A <GlossaryTerm term="dictionary">dict</GlossaryTerm> is a table of pairs. Each pair has a <GlossaryTerm term="key" />, the name you look things up by, and a value. It is written like a list with an even number of elements: key, value, key, value. Each key appears only once.

`dict get` looks a value up by its key. `dict set` adds a pair, or changes the value of a key that is already there. Like `incr` and `lappend`, `dict set` takes the variable's **name**, without `$`, because it changes the variable. `dict keys` gives the list of keys.

<WorkedExample
  code={`set gdsNumbers [dict create ACTIVE 1.0 POLY 2.0 METAL1 4.0]
puts [dict get $gdsNumbers POLY]
dict set gdsNumbers METAL2 6.0
puts [dict keys $gdsNumbers]
puts [dict size $gdsNumbers]
puts $gdsNumbers`}
  notes={{
    1: 'A dict with three pairs: a layer name, then its GDS number.',
    2: 'Look up the value of the key POLY. Output: 2.0',
    3: 'Add a pair. The NAME gdsNumbers, without $, because the variable changes.',
    4: 'The keys, in the order they were added. Output: ACTIVE POLY METAL1 METAL2',
    5: 'The number of pairs. Output: 4',
    6: 'A dict is a value you can print, like a list of pairs. Output: ACTIVE 1.0 POLY 2.0 METAL1 4.0 METAL2 6.0'
  }}
/>

## dict for walks in order

`dict for {key value} $d {body}` runs the body once per pair, like `foreach` with two variables. It walks the pairs in <GlossaryTerm term="insertion-order">insertion order</GlossaryTerm>: the order in which the keys were first added. That makes a dict a good choice for a report that must keep the order of a table.

Two rules to remember. A new key goes at the end. Setting a key that is already there changes its value but keeps its place.

<TclPlayground client:visible code={`set gdsNumbers [dict create ACTIVE 1.0 POLY 2.0 CONTACT 3.0]
dict for {name gds} $gdsNumbers {
    puts "$name is GDS $gds"
}`} />

## Records inside a dict

A value can be a dict itself. Then each layer holds a small record with named fields: `{number 2 datatype 0 purpose drawing}`. This is a nested dict, like the nested lists of Week 6.

With several keys, `dict set` and `dict get` go one level deeper per key, from the outside in: `dict set layers POLY number 2` sets the field `number` of the record `POLY`. `dict exists` takes the same keys and gives 1 or 0. Test with it before you read a key that might be missing.

<Diagram name="w09-nested" alt="The dict layers with two keys, POLY and METAL2. The value of each key is a record with three fields: number 2, datatype 0, purpose drawing for POLY; number 6, datatype 0, purpose drawing for METAL2. dict get layers METAL2 number goes in through METAL2, then through number, and gives 6. dict get layers POLY gives the whole record: number 2 datatype 0 purpose drawing." />

<WorkedExample
  code={`set layers [dict create]
dict set layers POLY number 2
dict set layers POLY datatype 0
dict set layers POLY purpose drawing
dict set layers METAL2 number 6
dict set layers METAL2 datatype 0
dict set layers METAL2 purpose drawing
puts [dict get $layers POLY]
puts [dict get $layers METAL2 number]
puts [dict exists $layers METAL2 purpose]
puts [dict exists $layers METAL7]`}
  notes={{
    1: 'An empty dict.',
    2: 'Two keys: the record POLY, then its field number. The record is created on the way.',
    3: 'A second field in the same record.',
    4: 'A third field. Datatype 0 means drawing in this course.',
    5: 'The record METAL2, the same way.',
    6: 'Its datatype.',
    7: 'Its purpose.',
    8: 'One key gives the whole record. Output: number 2 datatype 0 purpose drawing',
    9: 'Two keys give one field. Output: 6',
    10: 'Does METAL2 have a field purpose? Output: 1',
    11: 'There is no layer METAL7. dict exists says so without an error. Output: 0'

## Common traps

<Trap
  wrong={`set gdsNumbers [dict create METAL1 4.0 METAL2 6.0]
puts [dict get $gdsNumbers metal1]`}
  error={`key "metal1" not known in dictionary`}
  fix={`set gdsNumbers [dict create METAL1 4.0 METAL2 6.0]
set name metal1
if {[dict exists $gdsNumbers $name]} {
    puts [dict get $gdsNumbers $name]
} else {
    puts "$name is not a key"
}`}
  why="Keys are exact, and capitals count: metal1 is not METAL1. dict get on a key that is not there stops the script. When a key might be missing, test it first with dict exists, or clean the name with string toupper (Week 8)."
/>

<Trap
  wrong={`set gdsNumbers [dict create METAL1 4.0]
dict set $gdsNumbers METAL2 6.0
puts $gdsNumbers`}
  output={`METAL1 4.0`}
  fix={`set gdsNumbers [dict create METAL1 4.0]
dict set gdsNumbers METAL2 6.0
puts $gdsNumbers`}
  why="dict set wants the NAME of the variable. With $, Tcl first replaces $gdsNumbers with its value, so dict set creates a new variable with the strange name 'METAL1 4.0'. gdsNumbers itself never changes, and there is no error to warn you. Write the name without $, as with incr and lappend."
/>

<Trap
  wrong={`set gdsNumbers [dict create ACTIVE 1.0 POLY 2.0]
dict for {name} $gdsNumbers {
    puts $name
}`}
  error={`must have exactly two variable names`}
  fix={`set gdsNumbers [dict create ACTIVE 1.0 POLY 2.0]
dict for {name gds} $gdsNumbers {
    puts $name
}`}
  why="dict for always hands over a key AND its value, so it needs two variable names in its first word, even if the body uses only one of them."
/>
