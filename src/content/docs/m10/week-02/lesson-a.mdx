## A calculator command: expr

The command `expr` works out a sum, called an <GlossaryTerm term="expression" />. To see the answer, write it like this:

`puts [expr {400 * 300}]`

Read it as "print the result of this maths". The square brackets mean "do this first, then use the answer": Lesson B explains them. The braces hold the maths: Week 3 explains why. Until then, always write both, exactly like this.

Computers use `*` for times and `/` for divide, because × and ÷ are hard to type. These symbols are <GlossaryTerm term="operator">operators</GlossaryTerm>. Run the sum, then change the numbers and try `+` and `-`.

<TclPlayground client:visible code={`puts [expr {400 * 300}]`} />

## The order of operations

expr follows the same <GlossaryTerm term="order-of-operations" /> as school maths: `*` and `/` come before `+` and `-`, and anything in parentheses `( )` comes first of all.

expr can also read variables. Inside the braces, `$chipWidth` gives the value of `chipWidth`, so you can write the sum with names instead of numbers.

<WorkedExample
  code={`set chipWidth 400
set chipHeight 300
puts [expr {$chipWidth * $chipHeight}]
puts [expr {2 * ($chipWidth + $chipHeight)}]
puts [expr {2 * $chipWidth + $chipHeight}]`}
  notes={{
    1: 'The chip is 400 µm wide.',
    2: 'And 300 µm high.',
    3: 'The area: width times height. expr looks up both variables itself. Output: 120000',
    4: 'The perimeter, the distance all the way round. The parentheses make expr add first: 2 * 700. Output: 1400',
    5: 'The same numbers without parentheses. Now * comes first: 2 * 400 is 800, plus 300. Output: 1100. A different answer, so parentheses matter.'
  }}
/>

## Whole numbers and decimals

expr knows two kinds of numbers. An <GlossaryTerm term="integer" /> is a whole number, like 400. A <GlossaryTerm term="decimal-number" /> has a point, like 2.5 or 400.0.

The rule: if both numbers in a division are integers, the answer is an integer too, and the part after the point is dropped. This is <GlossaryTerm term="integer-division" />. If at least one number has a point, the answer is a decimal. The `%` operator gives the <GlossaryTerm term="remainder" />: what is left over after an integer division.

<Diagram name="w02-strip" alt="A strip of silicon 1000 micrometres long holds two Lumen-1 chips, each 400 micrometres wide, with 200 micrometres left over at the end. Below: 1000 divided by 400 gives 2, because whole numbers in give a whole number out; 1000 remainder 400 gives 200, the part left over; 1000 divided by 400.0 gives 2.5, a decimal, but half a chip is useless." />

<WorkedExample
  code={`set stripLength 1000
set chipWidth 400
puts [expr {$stripLength / $chipWidth}]
puts [expr {$stripLength % $chipWidth}]
puts [expr {$stripLength / 400.0}]`}
  notes={{
    1: 'A strip of silicon 1000 µm long.',
    2: 'Each chip is 400 µm wide.',
    3: 'Two integers, so integer division: 2.5 becomes 2. Here that is exactly what you want, because only whole chips count. Output: 2',
    4: 'The remainder: 2 chips use 800 µm, and 200 µm is left over. Output: 200',
    5: '400.0 has a point, so the answer is a decimal. Output: 2.5. Good maths, but you cannot sell half a chip.'
  }}
/>

## Predict → Run → Explain

Type your prediction first. A wrong prediction is useful: it shows you exactly which rule to fix.

<PredictOutput
  client:visible
  code={`puts [expr {300 / 400}]
puts [expr {300 / 400.0}]`}
  expected={`0
0.75`}
  explanation="Line 1 divides two integers, so the answer is an integer: 0.75 loses everything after the point and becomes 0. In line 2, 400.0 is a decimal, so you get the real answer, 0.75."
/>

<PredictOutput
  client:visible
  code={`puts [expr {100 - 20 * 2}]
puts [expr {(100 - 20) * 2}]`}
  expected={`60
160`}
  explanation="In line 1, * comes before -, so expr works out 20 * 2 = 40 first, then 100 - 40 = 60. In line 2 the parentheses come first: 100 - 20 = 80, then 80 * 2 = 160."
/>

## Common traps

<Trap
  wrong={`puts [expr {900 / 400}]`}
  output={`2`}
  fix={`puts [expr {900 / 400.0}]`}
  why="This is the cost of one chip: a small test wafer costs 900 dollars and holds 400 chips. Both numbers are integers, so expr drops the .25 without any warning. The real cost is 2.25 dollars, and over a million chips that missing .25 is 250000 dollars. Make one of the numbers a decimal."
/>

<Trap
  wrong={`puts [expr {400 x 300}]`}
  error={`invalid bareword "x"`}
  fix={`puts [expr {400 * 300}]`}
  why="x is a letter, not an operator. expr does not know a word called x, and says so: a bareword is a plain word that expr does not understand. Use * for times."
/>

<Trap
  wrong={`puts [expr {120,000 / 1000}]`}
  error={`unexpected "," outside function argument list`}
  fix={`puts [expr {120000 / 1000}]`}
  why="Write big numbers without commas or spaces: 120000, not 120,000 or 120 000. To expr, a comma means something else, so it stops."
/>
