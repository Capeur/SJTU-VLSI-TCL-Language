## Square brackets run a command first

When Tcl meets `[`, it runs everything up to the matching `]` as a command of its own. The <GlossaryTerm term="result" /> of that command then takes the place of the brackets. Only after that does the outer command run. This is called <GlossaryTerm term="command-substitution" />.

Every command gives back a result. expr gives back the answer to its sum. With brackets you hand that answer to another command: to `puts` to print it, or to `set` to keep it in a variable.

<Diagram name="w02-bracket-steps" alt="Three steps. Step 1: in set area, bracket expr 400 times 300 bracket, Tcl meets the opening bracket and runs what is inside as a new command. Step 2: expr 400 times 300 runs and gives back 120000. Step 3: the result takes the place of the brackets, so the command becomes set area 120000, and now set runs. A note says set never sees the brackets or the maths, only the number." />

<WorkedExample
  code={`set chipWidth 400
set chipHeight 300
set area [expr {$chipWidth * $chipHeight}]
puts "Area: $area um2"
puts "In mm2: [expr {$area / 1000000.0}]"`}
  notes={{
    1: 'The chip is 400 µm wide.',
    2: 'And 300 µm high.',
    3: 'The brackets run expr first. Its result, 120000, replaces them, so set gets two arguments: area and 120000. The variable area holds the number, not the maths.',
    4: 'um2 is how code writes µm², square micrometres. Output: Area: 120000 um2',
    5: 'Brackets work inside double quotes too: the result lands in the middle of the text. A square millimetre is 1000000 µm², and the .0 makes the answer a decimal. Output: In mm2: 0.12'
  }}
/>

## Brackets inside brackets

Brackets can sit inside brackets. This is called <GlossaryTerm term="nesting" />. Tcl reads from left to right, and at each `[` it starts a new command. A command can only run once all its words are ready, so the innermost command finishes first, and its result moves outwards.

One more fact makes nesting useful: `set` also gives back a result, the value it has just stored. So `[set area …]` stores a value and passes it on, in one go.

<Diagram name="w02-nesting" alt="The command puts, bracket set area, bracket expr 400 times 300, close brackets. The outer brackets start a new command, set area. While reading the words of set, Tcl meets the inner brackets. The order things finish in: 1, expr 400 times 300 gives 120000; 2, set area 120000 stores the number and gives back 120000; 3, puts 120000 prints it. A note says a command runs only when all its words are ready, so the innermost one finishes first." />

<WorkedExample
  code={`puts [set area [expr {400 * 300}]]
puts "Stored: $area"`}
  notes={{
    1: 'Tcl starts the outer brackets: a new command, set area …. Reading its words, Tcl meets the inner brackets and runs expr {400 * 300}, which gives 120000. Now set area 120000 runs: it stores the number and gives it back. Finally puts prints it. Output: 120000',
    2: 'The variable area kept the value. Output: Stored: 120000'
  }}
/>

Nesting saves lines, but a long nested line is hard to read and hard to check. When a sum has several steps, give each step its own line and its own variable. The two bottom blocks of {chip.name}, CORE and SRAM, are both 160 µm high:

<TclPlayground client:visible code={`set coreArea [expr {200 * 160}]
set sramArea [expr {140 * 160}]
set bothArea [expr {$coreArea + $sramArea}]
puts "CORE: $coreArea um2"
puts "SRAM: $sramArea um2"
puts "Both: $bothArea um2"`} />

## Common traps

<Trap
  wrong={`set area [400 * 300]`}
  error={`invalid command name "400"`}
  fix={`set area [expr {400 * 300}]`}
  why="Brackets run a command, so the first word inside them must be a command name. 400 is not a command. Maths always needs expr."
/>

<Trap
  wrong={`set area expr {400 * 300}`}
  error={`wrong # args: should be "set varName ?newValue?"`}
  fix={`set area [expr {400 * 300}]`}
  why="Without brackets, expr is just a word. set gets three arguments, area, expr and the maths, but it takes at most two. The brackets make expr run first, so set gets only its result."
/>

<Trap
  wrong={`puts "Area: expr {400 * 300} um2"`}
  output={`Area: expr {400 * 300} um2`}
  fix={`puts "Area: [expr {400 * 300}] um2"`}
  why="Without brackets, nothing runs: the word expr and the maths are printed as plain text. No error appears, so this one is easy to miss. Always read your output."
/>
