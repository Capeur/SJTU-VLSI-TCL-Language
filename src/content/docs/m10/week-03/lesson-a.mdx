## Words and grouping

You already know that Tcl cuts every command into <GlossaryTerm term="word">words</GlossaryTerm> at the spaces. The first word is the command name. The other words are its <GlossaryTerm term="argument">arguments</GlossaryTerm>.

That works until a sign needs a space in it. In `puts Hello chip`, puts gets two arguments, `Hello` and `chip`. When puts gets two arguments, it thinks the first one names the place to print to, so it stops with an error.

The fix is <GlossaryTerm term="grouping" />: you tell Tcl that several pieces with spaces between them form one word. Tcl has two ways to group, double quotes and braces. They group in the same way but treat the inside very differently.

<Diagram name="w03-word-split" alt="Two rows of word boxes. Without grouping, puts Hello chip is cut into three words, and puts fails because it takes Hello as the place to print to. With double quotes, puts Hello chip in quotes is cut into two words, and puts prints Hello chip." />

Run this line and read the error. Then put double quotes around `Hello chip` and run it again.

<TclPlayground client:visible code={`puts Hello chip`} fails={`can not find channel named "Hello"`} />

## Double quotes: group, then substitute

<GlossaryTerm term="double-quotes">Double quotes</GlossaryTerm> make one word from everything up to the next quote mark. Inside them, Tcl still does every <GlossaryTerm term="substitution" />: `$name` becomes the variable's value, and `[ ]` runs a command (<GlossaryTerm term="command-substitution" />). The quote marks themselves are not printed.

Use double quotes when your text should contain values, like a sign that shows a block's real name and size.

<WorkedExample
  code={`set block CORE
set width 200
puts "Block $block is $width um wide"
puts "Half of it: [expr {$width / 2}] um"`}
  notes={{
    1: 'set stores CORE in the variable block.',
    2: 'set stores 200 in width. Lumen-1 measures everything in micrometres, written um in code.',
    3: 'The quotes make one word. Inside it, $block becomes CORE and $width becomes 200, so puts gets one argument: Block CORE is 200 um wide.',
    4: 'Inside the quotes, the brackets run expr first. Its result, 100, takes the place of the brackets: Half of it: 100 um.'
  }}
/>

Run it and check that the output matches the notes:

<TclPlayground client:visible code={`set block CORE

puts "Half of it: [expr {$width / 2}] um"`} />

## Braces freeze everything

<GlossaryTerm term="braces">Braces</GlossaryTerm> also make one word, but nothing inside them changes. A `$` stays a dollar sign, brackets stay brackets. The result is <GlossaryTerm term="literal" /> text, exactly as you typed it.

Use braces when you want text exactly as written: a price with a `$` in it, or a line of Tcl code you want to show. You have used braces since Week 2 in `expr {…}`. They freeze the maths so that expr, not the normal rules, works it out. Lesson B explains why that matters.

Here is the same sign as before, now in braces. Predict the output, then run it:

<TclPlayground client:visible code={`set block CORE
set width 200
puts {Block $block is $width um wide}`} />

## Inside [ ], a new command starts

Braces only group when they are the first character of a word. Inside double quotes, a brace is not the start of a word. It is just a character: it gets printed, and `$` next to it is still replaced. **The outer grouping decides.**

Square brackets are different. When Tcl meets `[`, it reads what follows as a brand-new command, up to the matching `]`. That new command is cut into words from scratch, so braces inside the brackets group again. This is why `"[expr {$w * 2}]"` works inside quotes, while `"{$w}"` keeps its braces and still substitutes `$w`.

<Diagram name="w03-outer-grouping" alt="The line puts, quote, Size brace dollar w brace is bracket expr brace dollar w times 2 brace bracket, quote, with w equal to 3. The outer quotes form one word where substitution happens. Inside it, the braces around dollar w are plain characters, so they are printed and dollar w becomes 3. The square brackets start a new command, where the braces group again, so expr receives dollar w times 2. The printed result is Size brace 3 brace is 6." />

<WorkedExample
  code={`set block CORE
set width 200
puts {Block $block, half width [expr {$width / 2}]}
puts "Block {$block}, half width [expr {$width / 2}]"`}
  notes={{
    1: 'The same two variables as before.',
    2: 'Width of CORE in um.',
    3: 'Braces on the outside freeze everything, even the brackets. Output: Block $block, half width [expr {$width / 2}]',
    4: 'Quotes on the outside. The braces around $block are just characters, so the output shows {CORE}. The brackets start a new command, where {$width / 2} is a real braced word for expr. Output: Block {CORE}, half width 100'
  }}
/>

## Common traps

Each trap shows the real message Tcl gives. Error messages are your friend: they usually name the exact problem.

<Trap
  wrong={`set block CORE
puts "Block $block is ready`}
  error={`missing "`}
  fix={`set block CORE
puts "Block $block is ready"`}
  why="Every opening quote needs a closing quote. Without it, Tcl keeps reading to the end of the script, looking for the end of the word. The same goes for braces: every { needs a matching }."
/>

<Trap
  wrong={`puts "Price: $5 per chip"`}
  error={`can't read "5": no such variable`}
  fix={`puts {Price: $5 per chip}`}
  why="Inside double quotes, $5 asks for a variable named 5, which does not exist. Braces stop substitution, so the dollar sign is printed. Lesson B shows a second fix that works inside quotes."
/>

<Trap
  wrong={`set label M1
puts "Layer "$label" is metal 1"`}
  error={`extra characters after close-quote`}
  fix={`set label M1
puts "Layer $label is metal 1"`}
  why="A quote only groups at the start of a word, and a closing quote must be followed by a space or the end of the line. Here the second quote closes the word, and Tcl finds $label glued right after it. To print quote marks inside a quoted word, Lesson B shows you how."
/>
