## Backslash: switch off one character

A <GlossaryTerm term="backslash-escape">backslash</GlossaryTerm> `\` changes the meaning of the character right after it. It has two jobs.

First, it turns a special character into an ordinary one. `\$` is a real dollar sign, so no variable is read. Second, before some letters it makes an invisible character, such as a new line.

| You type | You get |
|---|---|
| `\$` | a dollar sign; no variable is read |
| `\"` | a quote mark that does not end the word |
| `\[` | a square bracket; no command runs |
| `\\` | one backslash |
| `\n` | a new line |
| `\t` | a tab, which jumps to the next column |

Backslashes work inside double quotes and in plain words. Inside braces they stay exactly as typed, like everything else.

<WorkedExample
  code={String.raw`set block CORE
set cost 12
puts "Block\tCost"
puts "\"$block\"\t\$$cost"`}
  notes={{
    1: 'The block name.',
    2: 'Its cost, in dollars per chip.',
    3: 'Each \\t becomes a tab, so the two titles start in different columns.',
    4: 'Each \\" prints a quote mark without ending the word. $block still becomes CORE. Then \\t is a tab, \\$ prints a real dollar sign, and $cost becomes 12.'
  }}
/>

## The rules in plain words

The whole Tcl language rests on twelve rules, known as the <GlossaryTerm term="dodekalogue" />. You have met most of them already. The diagram puts them together as the five steps Tcl follows for every command.

<Diagram name="w03-read-a-line" alt="A flow of five steps. Step 1: find where the command ends, at a new line or a semicolon; a hash where a command starts begins a comment. Step 2: cut the command into words at the spaces; quotes and braces keep a word together. Step 3, highlighted: substitute dollar names, square-bracket commands and backslashes in each word, left to right, exactly once; nothing inside braces changes; a value that comes in is never read again and never splits a word. Step 4: the first word names the command. Step 5: run the command with the other words; the command decides what they mean. Each step lists the matching rule numbers." />

Step 3 holds the rule that surprises most people: **Tcl substitutes only once.** If a variable's value looks like `$name` or `[command]`, Tcl does not read it a second time. And a value with spaces in it stays one word.

Step 1 explains <GlossaryTerm term="comment">comments</GlossaryTerm>: `#` starts a comment only where a new command could start. To add a note after a command, end the command first with a semicolon: `set width 200 ;# in um`.

<details>
<summary>For the curious: all 12 rules, one sentence each</summary>

The numbers match the official Tcl(n) manual page (see Further reading). This is a summary in our own words, not the official text.

| # | Rule | In plain words |
|---|---|---|
| 1 | Commands | A script is a list of commands, separated by new lines or semicolons, unless those are inside quotes or braces. |
| 2 | Evaluation | Tcl splits a command into words and substitutes; the first word picks the command, which then decides what the other words mean. |
| 3 | Words | Words are separated by spaces or tabs. |
| 4 | Double quotes | A word that starts with `"` ends at the next `"`; inside, spaces and `;` are ordinary, and `$`, `[ ]` and `\` still substitute. |
| 5 | Argument expansion | A word that starts with `{*}` is split into several words. You will meet it later in the course. |
| 6 | Braces | A word that starts with `{` ends at the matching `}`; braces can nest, and nothing inside is substituted (except a backslash at the very end of a line). |
| 7 | Command substitution | `[ … ]` runs what is inside as a new command, and its result replaces the brackets. |
| 8 | Variable substitution | `$name` is replaced by the variable's value. |
| 9 | Backslash substitution | `\` before a character makes it ordinary, or makes a special character such as `\n`; a `\` at the end of a line joins it to the next line. |
| 10 | Comments | `#` where Tcl expects the first word of a command starts a comment that runs to the end of the line. |
| 11 | Order of substitution | Tcl reads each character once, left to right, and never re-reads the result of a substitution. |
| 12 | Substitution and word boundaries | Substitution never changes where words begin and end: a value with spaces stays one word. |

</details>

## Always brace your expr

Since Week 2 you have written maths as `expr {…}` with braces. Now you can see why. The command `expr` is unusual: it does its own substitution when it reads an <GlossaryTerm term="expression" />.

With braces, Tcl leaves the expression alone and expr reads each variable as one value. Without braces, Tcl substitutes first, then expr reads the result again as maths. That is two passes, and a value that looks like maths changes the answer. Braced expr is also faster.

<Diagram name="w03-brace-expr" alt="Two columns for the variable extra holding the text 4 plus 1. Without braces, Tcl substitutes first, so expr receives 4 plus 1 times 2, does the times first, and gives 6: a wrong number with no warning. With braces, expr receives dollar extra times 2, looks up extra itself, gets the single value 4 plus 1, which is not a number, and gives an error message that tells you the value is wrong." />

<WorkedExample
  code={`set extra "4 + 1"
puts [expr $extra * 2]`}
  notes={{
    1: 'Imagine a teammate typed this value as a formula instead of the number 5.',
    2: 'No braces. Tcl substitutes first, so expr receives 4 + 1 * 2. It reads that as maths, does * before +, and prints 6. Not 10, and no warning.'
  }}
/>

<VersionNote
  since="9.0"
  code86={`set extra "4 + 1"
puts [expr {$extra * 2}]`}
  fails86={`can't use non-numeric string as operand of "*"`}
  code90={`set extra "4 + 1"
puts [expr {$extra * 2}]`}
  fails90={`cannot use a list as left operand of "*"`}
>
With braces, expr reads `$extra` as one value, `4 + 1`, which is not a number, so it stops with an error. The wording of the message changed in Tcl 9.0, but the point is the same on both versions: **an error, not a wrong number**. An error tells you that something is wrong. A wrong number hides it.
</VersionNote>

## Common traps

<Trap
  wrong={String.raw`puts {CORE\nSRAM}`}
  output={String.raw`CORE\nSRAM`}
  fix={String.raw`puts "CORE\nSRAM"`}
  why="Braces freeze backslashes too, so \n stays as two characters. Use double quotes when you want \n to become a new line."
/>

<Trap
  wrong={String.raw`puts "D:\temp\notes.txt"`}
  output={"D:\temp\notes.txt"}
  fix={String.raw`puts {D:\temp\notes.txt}`}
  why="Windows folder names use backslashes, and inside quotes \t is a tab and \n is a new line. Put such paths in braces, or write them with forward slashes (D:/temp/notes.txt), which Tcl also understands on Windows."
/>

<Trap
  wrong={`set width 200 # in um
puts $width`}
  error={`wrong # args: should be "set varName ?newValue?"`}
  fix={`set width 200 ;# in um
puts $width`}
  why="A # starts a comment only where a command could start. Here it is just another word for set, and set takes at most two. The semicolon ends the command, so the # after it starts a comment."
/>
