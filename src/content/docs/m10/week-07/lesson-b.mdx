## Each proc has its own variables

In the city map, think of each proc as a building with its own rooms. Every call of a proc starts with an empty set of variable boxes: its arguments and nothing else. A variable you set inside it is a <GlossaryTerm term="local-variable">local variable</GlossaryTerm>. It disappears when the proc returns.

So a proc cannot see the script's variables, and the script cannot see the proc's. Two variables with the same name, one inside and one outside, are two different boxes. That is a good thing: a proc cannot change your data by accident.

The usual way in is an argument. The usual way out is return.

<Diagram name="w07-scope" alt="Two buildings side by side. The big one is the main script, with a box called width holding 999. The small one is a call of rectWidth, with its own boxes: rect holding 20 20 220 180 and width holding 200. An arrow labelled argument carries the rectangle in, and an arrow labelled return carries 200 out. The two boxes called width are separate: the 999 outside never changes." />

<WorkedExample
  code={`set width 999
proc rectWidth {rect} {
    set width [expr {[lindex $rect 2] - [lindex $rect 0]}]
    return $width
}
puts [rectWidth {20 20 220 180}]
puts $width`}
  notes={{
    1: 'A variable of the main script.',
    2: 'A proc with one argument, rect.',
    3: 'This width is a LOCAL variable of the call: a new box, not the one outside.',
    4: 'Send its value back.',
    5: 'The end of the proc. The local width disappears when the call ends.',
    6: 'Output: 200',
    7: 'The script’s own width was never touched. Output: 999'
  }}
/>

## global: facts the whole script shares

Some facts belong to the whole script, like the chip's size. Write `global chipWidth chipHeight` at the top of a proc's body. From then on, inside that proc, those two names mean the script's own variables, the <GlossaryTerm term="global-variable">global variables</GlossaryTerm>.

Use global sparingly. A proc that gets everything through its arguments is easier to test and to reuse. Keep global for a few facts that never change while the script runs.

This proc checks the right and top edges of a block. The capstone also checks the left and bottom ones.

<TclPlayground client:visible code={`set chipWidth 400
set chipHeight 300
proc insideChip {rect} {
    global chipWidth chipHeight
    set rightOk [expr {[lindex $rect 2] <= $chipWidth}]
    set topOk [expr {[lindex $rect 3] <= $chipHeight}]
    return [expr {$rightOk && $topOk}]
}
puts [insideChip {20 20 220 180}]
puts [insideChip {380 200 420 280}]`} />

## upvar: change the caller's variable

A proc gets copies of values, so it cannot change the caller's variables. But `incr` and `lappend` do change variables: you give them a variable's NAME, without `$`. Your own procs can work the same way with `upvar`.

`upvar 1 $rectName rect` means: go 1 level up, to the caller, find the variable whose name is in `rectName`, and let me call it `rect` here. After that line, reading or setting `rect` reads or sets the caller's variable. M10 needs only this one pattern.

<Diagram name="w07-upvar" alt="The main script has a box called sensor holding 160 200 260 280. The call moveRight sensor 10 passes the word sensor, a name, not the rectangle. Inside the proc, upvar 1 dollar rectName rect draws a link from the proc's name rect to the script's box sensor. When the proc sets rect, the script's sensor changes to 170 200 270 280." />

<WorkedExample
  code={`proc moveRight {rectName dx} {
    upvar 1 $rectName rect
    set x1 [expr {[lindex $rect 0] + $dx}]
    set x2 [expr {[lindex $rect 2] + $dx}]
    set rect [list $x1 [lindex $rect 1] $x2 [lindex $rect 3]]
}
set sensor {160 200 260 280}
moveRight sensor 10
puts "SENSOR: $sensor"`}
  notes={{
    1: 'The first argument is a variable NAME, like the first argument of incr.',
    2: 'Link the local name rect to the caller’s variable whose name is in rectName.',
    3: 'Reading rect reads the caller’s rectangle: 160 + 10 = 170.',
    4: '260 + 10 = 270.',
    5: 'Setting rect sets the caller’s variable.',
    6: 'The end of the proc.',
    7: 'SENSOR’s corners.',
    8: 'Pass the name sensor, without a $.',
    9: 'The script’s variable has changed. Output: SENSOR: 170 200 270 280'
  }}
/>

## args: any number of arguments

If the last argument in the list is called `args`, the proc accepts any number of values. They all arrive as one list in `args`, so you can walk it with foreach.

<TclPlayground client:visible code={`proc largest {args} {
    set best [lindex $args 0]
    foreach value $args {
        if {$value > $best} {
            set best $value
        }
    }
    return $best
}
puts [largest 200 140 120]
puts [largest 80 160]`} />

## Common traps

<Trap
  wrong={`set chipWidth 400
proc fitsWidth {rect} {
    return [expr {[lindex $rect 2] <= $chipWidth}]
}
puts [fitsWidth {20 20 220 180}]`}
  error={`can't read "chipWidth": no such variable`}
  fix={`set chipWidth 400
proc fitsWidth {rect} {
    global chipWidth
    return [expr {[lindex $rect 2] <= $chipWidth}]
}
puts [fitsWidth {20 20 220 180}]`}
  why="Inside the proc, chipWidth is a local name, and no local variable has that name. The script's chipWidth is in another building. Name it with global at the top of the body, or better, pass it as an argument."
/>

<Trap
  wrong={`proc moveRight {rectName dx} {
    upvar 1 $rectName rect
    set x1 [expr {[lindex $rect 0] + $dx}]
    set x2 [expr {[lindex $rect 2] + $dx}]
    set rect [list $x1 [lindex $rect 1] $x2 [lindex $rect 3]]
}
set sensor {160 200 260 280}
moveRight $sensor 10`}
  error={`can't read "rect": no such variable`}
  fix={`proc moveRight {rectName dx} {
    upvar 1 $rectName rect
    set x1 [expr {[lindex $rect 0] + $dx}]
    set x2 [expr {[lindex $rect 2] + $dx}]
    set rect [list $x1 [lindex $rect 1] $x2 [lindex $rect 3]]
}
set sensor {160 200 260 280}
moveRight sensor 10`}
  why="With $sensor, the proc receives the rectangle 160 200 260 280 instead of the name sensor. upvar then links rect to a caller's variable with that strange name. No such variable exists, so the first line that reads rect stops with an error. A proc that uses upvar wants the name, without $, just like incr and lappend."
/>

<Trap
  wrong={`proc largest {args} {
    set best [lindex $args 0]
    foreach value $args {
        if {$value > $best} {
            set best $value
        }
    }
    return $best
}
puts [largest {200 140 120}]`}
  output={`200 140 120`}
  fix={`proc largest {args} {
    set best [lindex $args 0]
    foreach value $args {
        if {$value > $best} {
            set best $value
        }
    }
    return $best
}
puts [largest 200 140 120]`}
  why="args collects the WORDS of the call. In braces, the three numbers are one word, so args holds one element: the whole list. foreach runs once and gives that list back. Pass the numbers as separate words."
/>
