## Goal

**Write the two procs at the heart of the M10 capstone, `rectArea` and `rectOverlaps`, and use them to find the blocks that clash in a floorplan.**

Why it matters for chips: a teammate has drawn a <GlossaryTerm term="floorplan" /> for the inside of {chip.name}'s CORE block. It splits the processor into five smaller blocks: ALU (the arithmetic unit, which adds and compares), REGS (registers, tiny fast stores), CTRL (control), CACHE (a small fast memory) and FPU (the unit for decimal maths). Before anyone draws the shapes inside them, the plan must be clean: no two blocks may overlap or touch. Your script checks it. The capstone, TinyLayout in M20, and your Week 37 checks all reuse these two procs.

## Specification

- **Input.** The starter gives you one line: `set plan {…}`, a nested list with one `{name {x1 y1 x2 y2}}` pair per block, in µm. **Keep this line exactly as it is.** The checker changes it twice and runs your script again.
- **`rectArea rect`** returns the area of one rectangle, (x2 − x1) × (y2 − y1).
- **`rectOverlaps a b`** returns `1` if the two rectangles clash and `0` if there is space between them. **Touching counts as a clash**, along an edge or at a single corner: our blocks need space between them. Use the course rule, `x1a <= x2b && x1b <= x2a && y1a <= y2b && y1b <= y2a`, where a is `{x1a y1a x2a y2a}` and b is `{x1b y1b x2b y2b}`. A gap of even 1 µm means no clash, and `rectOverlaps $a $b` must give the same answer as `rectOverlaps $b $a`.
- **Output.** With this input, your script must print exactly:

<pre class="tc-code" tabindex="0">{expected.trimEnd()}</pre>

- **One area line per block**, in the order of `plan`.
- **One Conflict line per clashing pair**, each pair once. The first name comes before the second in `plan`. Then the number of conflicts.
- Words, capitals and punctuation must match. Extra spaces are forgiven.

The checker does not only read your output. It also **calls your two procs** with its own test rectangles: touching edges, touching corners, 1 µm gaps, one rectangle inside another, identical rectangles, each pair in both orders. So use exactly these names, with one argument for rectArea and two for rectOverlaps.

## Step by step

Press **Run** after every step. For steps 1 and 2, test your proc with a few calls of your own, such as `puts [rectOverlaps {0 0 10 10} {10 0 20 10}]`, then delete those test lines.

1. **rectArea.** Write `proc rectArea {rect} {…}`. Use lindex for the corners and return the area.
2. **rectOverlaps.** Write `proc rectOverlaps {a b} {…}`. Test the x spans like `spansOverlap` in Lesson A, then the y spans, and return both joined with `&&`.
3. **Areas.** `foreach block $plan {…}`: the name is `lindex $block 0` and the rectangle is `lindex $block 1`. Print one line per block.
4. **Every pair.** Use the pair loop from Lesson A: i from 0, j from i + 1. Get the two rectangles with `lindex $plan $i 1` and `lindex $plan $j 1`. If rectOverlaps gives 1, print the Conflict line and count it.
5. **Count.** After both loops, print the number of conflicts.
