## Glob patterns: string match

`string match pattern text` gives 1 if the text fits the pattern and 0 if not. The pattern comes first. It is a <GlossaryTerm term="glob-pattern">glob pattern</GlossaryTerm>, with three special signs: `*` means any characters, even none; `?` means exactly one character; `[A-Z]` means one character from a set, here any capital letter.

These are glob patterns, the same small language a terminal uses for file names, and not <GlossaryTerm term="regular-expression">regular expressions</GlossaryTerm>, a bigger pattern language you meet in Week 15, where `*` means something else.

Always put a pattern in braces. A pattern with `[ ]` must be braced, or Tcl runs the brackets as a command (Week 3).

<Diagram name="w08-glob" alt="Three pattern tests. METAL?_* on METAL2_drawing gives 1: the question mark takes the single character 2 and the star takes drawing. METAL?_* on METAL10_drawing gives 0: the question mark takes only the 1, then the 0 does not match the underscore of the pattern. The braced pattern [A-Z]* on poly_drawing gives 0, because the first character p is not a capital letter. A note says glob patterns are not regular expressions, and patterns with brackets go in braces." />

<WorkedExample
  code={`puts [string match {METAL?_*} METAL2_drawing]
puts [string match {METAL?_*} METAL10_drawing]
puts [string match {*_pin} VIA1_pin]
puts [string match {[A-Z]*} poly_drawing]
puts [string match {*_*} ACTIVE]`}
  notes={{
    1: '? takes the 2, the _ matches, and * takes drawing. Output: 1',
    2: '? takes only ONE character, the 1. Then the 0 meets the _ of the pattern. Output: 0',
    3: '* takes VIA1, then _pin matches the end exactly. Output: 1',
    4: 'One capital letter, then anything. p is not a capital. Output: 0',
    5: 'Is there a _ anywhere? ACTIVE has none. Output: 0'
  }}
/>

## Predict → Run → Explain

A loop that keeps only the pin names. Type your prediction, then run it.

<PredictOutput
  client:visible
  code={`set names {POLY_pin METAL2_drawing VIA1_pin ACTIVE_drawing}
foreach name $names {
    if {[string match {*_pin} $name]} {
        puts "pin: $name"
    }
}
puts [string match {METAL?} METAL]`}
  expected={`pin: POLY_pin
pin: VIA1_pin
0`}
  explanation="Only the names that end in _pin fit *_pin, so the loop prints two lines. In the last line, ? needs exactly one character after METAL, and there is none, so the answer is 0. With * instead of ?, it would be 1, because * also matches nothing."
/>

## string map: swap pieces of text

`string map {from to} text` gives back a new string where every `from` is replaced with `to`. The first word is a list of pairs, so you can swap several things at once: `{from1 to1 from2 to2}`. A `to` can be empty, `""`, to delete a piece.

When the values come from variables, build the pairs with `list`, as in the last line below.

<TclPlayground client:visible code={`set typed METAL2-pin
puts [string map {- _} $typed]
puts [string map {_drawing ""} POLY_drawing]
set name CORE
set width 200
puts [string map [list NAME $name WIDTH $width] "NAME is WIDTH um wide"]`} />

## format: neat columns and rounded numbers

`format` builds a line of text from a pattern and some values. Each <GlossaryTerm term="format-specifier">format specifier</GlossaryTerm>, a code that starts with `%`, takes the next value, in order. `%s` prints text, `%d` a whole number, and `%.1f` a decimal number rounded to 1 place.

A number after the `%` sets the width of a column: `%6d` pads a number with spaces on the left, to 6 characters, and `%-7s` pads text on the right. `%%` prints a real percent sign.

<Diagram name="w08-format-fields" alt="The command format with the pattern percent minus 7 s, percent 6 d, um2, percent 5.1 f, percent percent, followed by the values name, area and share. Arrows link each specifier to a box: percent minus 7 s is text, 7 wide, padded on the right; percent 6 d is a whole number, 6 wide, padded on the left; percent 5.1 f is a decimal with 1 place, 5 wide, rounded; percent percent is a real percent sign and uses no value. Below, the result: CORE, 32000 um2, 26.7 percent, in neat columns." />

<WorkedExample
  code={`set chipArea [expr {400 * 300}]
foreach {name area} {CORE 32000 SRAM 22400 ADC 9600 SENSOR 8000 PADS 8000} {
    set share [expr {100.0 * $area / $chipArea}]
    puts [format "%-7s %6d um2 %5.1f%%" $name $area $share]
}`}
  notes={{
    1: 'The area of the whole chip: 120000 µm².',
    2: 'Week 5: foreach with two variables takes a name and an area each time.',
    3: '100.0 makes it a decimal division (Week 2). For CORE: 26.666666666666668',
    4: 'Name padded to 7, area 6 wide, share rounded to 1 place, then %. Output: CORE     32000 um2  26.7%, and so on down to PADS      8000 um2   6.7%',
    5: 'The end of the loop.'
  }}
/>

## Common traps

<Trap
  wrong={`set name POLY_drawing
puts [string match [A-Z]* $name]`}
  error={`invalid command name "A-Z"`}
  fix={`set name POLY_drawing
puts [string match {[A-Z]*} $name]`}
  why="Without braces, Tcl sees the brackets first and tries to run a command called A-Z, as in Week 3. Braces keep the pattern exactly as you typed it, so string match gets the brackets. Brace every pattern."
/>

<Trap
  wrong={`set name VIA1_pin
puts [string match $name {*_pin}]`}
  output={`0`}
  fix={`set name VIA1_pin
puts [string match {*_pin} $name]`}
  why="The pattern comes FIRST. Here Tcl uses VIA1_pin as the pattern and checks whether the text *_pin fits it. It does not, so you get 0, with no error to warn you."
/>

<Trap
  wrong={`puts [format "%s: %d um2" CORE]`}
  error={`not enough arguments for all format specifiers`}
  fix={`puts [format "%s: %d um2" CORE 32000]`}
  why="Each % code takes one value, in order. Here %s takes CORE, and %d finds nothing left. Count the % codes (not %%) and give that many values."
/>
